# SmartAccess 产品需求文档（PRD）

## 1. 文档说明

- 产品名称：`SmartAccess`
- 文档类型：产品需求文档（PRD）
- 当前阶段：`MVP -> V1` 基线规划
- 主形态：`PyQt` 桌面端 + UI 自动化 + 视觉识别 + SpecLabOS/FastAPI 对接
- 部署约束：实验室内网优先，可选外部模型，可本地替代

## 2. 产品概述

SmartAccess 是一个面向实验室科学仪器上位机软件的非侵入式智能接入层。它的目标不是替代仪器原生控制软件，而是在不强依赖厂商 SDK/API 的前提下，用 AI 交互、UI 自动化和视觉识别，把实验操作和状态采集标准化，并将实验数据、过程日志、异常信息和标准工作流模板统一接入 SpecLabOS。

SmartAccess 既是本地设备侧执行工作台，也是 SpecLabOS 在实验室终端侧的标准化执行入口。它通过桌面工作台、标准工作流模板和 FastAPI 服务，把本地设备侧执行、模板发布备份和平台下发回拉串成闭环。

## 3. 背景与问题

当前实验室的自动化和数字化建设常见以下问题：

- 仪器品牌和上位机软件差异大，统一接入难。
- 现有自动化多是单机脚本或人工 SOP，缺少标准工作流抽象。
- 实验过程中的关键状态依赖人工观察，难以实时记录与回放。
- 数据上传平台需要人工录入，实验参数与结果的一致性差。
- 出现执行异常时缺乏统一的告警、重试和恢复策略。
- 已验证的实验流程难以沉淀为可版本化、可回拉的模板资产。

SmartAccess 的任务是构建一个通用的实验执行与观测中间层，让更多仪器以较低改造成本接入标准化实验管理体系，并把标准工作流沉淀到 SpecLabOS 模板中心。

## 4. 目标与非目标

### 4.1 产品目标

- 让实验室可以在不修改上位机核心软件的前提下接入 SpecLabOS。
- 用 AI 引导非程序员配置实验工作流、ROI 区域和平台字段映射。
- 把 UI 操作、状态识别、实验日志和平台回传串成闭环。
- 让新仪器接入具备模板化、可复用、可回归的交付方式。
- 让标准化工作流可以发布到 SpecLabOS 模板中心，并支持按模板 ID 和版本再次下发执行。
- 提供统一工作台，使接入、设计、模板管理和运行监控在同一产品框架内完成。

### 4.2 非目标

- 不直接替代厂商的仪器控制逻辑、驱动或安全联锁系统。
- 不承诺在首版中支持所有品牌和全自动流程。
- 不在没有审计和安全约束的前提下执行高风险物理动作。
- 不在 MVP 阶段支持“完整模板直传”和“模板引用执行”双模式并存。

## 5. 目标用户

### 5.1 一线科研人员

- 诉求：快速把实验步骤标准化、减少重复操作、降低手工录入。
- 成功标准：可以通过对话或简单配置完成流程设计、模板复用与运行。

### 5.2 实验室管理人员

- 诉求：统一记录实验过程、掌握运行状态、沉淀模板和数据资产。
- 成功标准：可查看任务状态、日志、异常、模板版本和数据回传结果。

### 5.3 平台/自动化工程师

- 诉求：快速接入新仪器、维护平台字段映射、建立回归评测。
- 成功标准：新增一个仪器时有明确契约、模板、模板发布机制和验收路径。

## 6. 典型使用场景

### 场景 1：首次接入一台新仪器

用户选择仪器类型，标注窗口、按钮和读数区域，SmartAccess 生成基础仪器画像、校准结果和平台映射草稿。

### 场景 2：通过自然语言生成实验工作流

用户描述实验目标和步骤，AI Agent 结合既有模板和仪器画像生成 `workflow.yaml` 草稿，并提示关键前置条件与风险点。

### 场景 3：标准工作流发布到 SpecLabOS 模板中心

用户完成工作流校准、字段映射和复用性检查后，将标准工作流发布到 SpecLabOS。平台保存模板 ID、版本、适用仪器、发布时间和来源，用于备份、审计和后续下发。

### 场景 4：SpecLabOS 按模板版本下发任务

SpecLabOS 向 SmartAccess 下发包含 `template_id + template_version` 的任务。SmartAccess 拉取模板内容、绑定实验参数并启动执行，而不是依赖本地临时脚本。

### 场景 5：实验运行中的状态感知与监控

SmartAccess 在关键步骤前后采集截图，识别温度、压力、阶段状态和告警信息，把结构化结果写入运行轨迹，并在运行监控页展示当前步骤、识别结果和异常动作。

### 场景 6：异常中断后的恢复

当发现窗口失焦、按钮失效、OCR 读数异常或平台同步失败时，系统进入受控异常态，按恢复策略重试、回退或请求人工确认。

### 场景 7：实验数据、日志和模板复用闭环

SmartAccess 将实验参数、阶段状态、日志和关键截图上传至 SpecLabOS，并保留本地模板草稿、校准态和最近执行态，便于后续分析、审计、模板回滚和复用。

## 7. 产品范围

### 7.1 MVP 范围

- 支持 Windows 上位机场景。
- 支持单窗口仪器软件的基础校准和执行。
- 支持基于按钮点击、输入框填值、等待条件、截图校验的工作流执行。
- 支持 ROI 标注、OCR 读数、简单状态识别。
- 支持任务配置下发、状态上报、日志上传和参数映射。
- 支持标准工作流在完成校准后发布到 SpecLabOS 模板中心，并按模板 ID + 版本回拉执行。
- 支持 `GET /health`、`POST /api/v1/experiment/trigger`、`POST /api/v1/experiment/execute`、`GET /api/v1/experiment/status` 四个设备侧 FastAPI 基线接口。
- 支持工作台首页、设备接入与校准页、工作流设计页、模板库页、运行监控页五类核心页面。
- 支持运行监控中的步骤时间线、观测/审计标签页和日志标签页。
- 支持模板库的本地版本查找、状态过滤、版本时间线、发布版本切换式回滚和基础版本维护。
- 支持工作流步骤级观测条件，按 OCR、presence、template、color、none 等模式完成动作后识别闭环。
- 支持锚点 normalized ROI，在窗口尺寸变化时按当前窗口尺寸重新映射坐标。
- 支持本地日志、异常告警和人工确认恢复。

### 7.1.1 VER3 扩展范围

- **真实视觉链路**：PaddleOCR 文本识别、OpenCV 模板匹配、HSV 颜色检测、前景占比存在性检测，全部本地执行。
- **真实动作链路**：Win32 SendInput/SetCursorPos 驱动 click、double_click、type、hotkey、press_enter、wait。
- **仪器删除能力**：安全/确认表行级删除；已校准仪器右键删除 + 引用预检（运行中 session 拒删，被引用允许高风险确认但不级联）。
- **工作流删除能力**：草稿本地删除；本地模板副本云端优先删除（云端失败则本地保留）。
- **AI 运行时知识库**：workspace/ai-runtime/ 下 memory/skill pending/approved 管理；生成时检索已批准知识；生成后自动抽取候选；推理面板展示命中 ID。
- **秒制强制约束**：DeepSeek prompt 显式要求秒单位；生成后自动标准化 ms→s；>=1000 的裸数字视为毫秒换算；301-999 发出人工确认警告。
- **wait_until 真实轮询**：编排器按 poll_interval_seconds 轮询 observer 直到命中或 timeout_seconds 超时。
- **screenshot_check 一次性观测**：不再假睡眠，改为一次观测 + 条件判断。
- **Provider 独立装配**：桌面默认 Win32 自动化 + PaddleOCR 本地视觉；状态栏实时显示模式；依赖缺失 fail fast。

### 7.2 V1 范围

- 增强多窗口、多页面切换和更复杂的条件分支。
- 支持 Linux 上位机场景。
- 支持模板市场、批量仪器画像管理、角色权限细化。
- 支持更强的视觉模式库和多模态状态识别。
- 支持更完整的任务队列、并发调度和可视化监控。
- 支持更细粒度的模板审核、发布审批和回滚治理。

### 7.3 暂不纳入范围

- 直接控制底层驱动或 PLC。
- 未经审批的全自动危险动作执行。
- 面向公网的多租户 SaaS 形态。
- 在 MVP 中支持完整模板直传执行。

## 8. 核心功能需求

### 8.1 仪器接入与校准

- 支持创建仪器画像，包括窗口签名、锚点、动作列表和安全限制。
- 支持用户框选按钮、输入框、状态读数区和告警区。
- 支持校准结果保存为可复用模板。
- 支持将仪器画像与平台字段映射关联。
- 支持为工作流标准化阶段补充适用仪器、校准状态和可复用说明。

### 8.2 AI 引导式工作流生成

- 支持自然语言描述实验步骤并生成工作流草稿。
- 支持引用已有模板、仪器画像和平台字段作为上下文。
- 支持工作流中的前置条件、步骤、输出、重试策略和步骤级观测条件编辑。
- 支持 `roi_bindings` 以“工作流逻辑名 -> 已校准锚点”的方式复用同一仪器画像锚点。
- 支持 `outputs` 以“结果 key -> 观测来源/模式”的方式声明运行后保留结果。
- 支持版本化保存和二次修改。
- 支持在工作流完成校准和字段映射后进入 `Standardized` 状态。
- 支持发布前填写模板标识、版本说明、来源和适用仪器。

### 8.3 ROI 标注与状态识别

- 支持矩形 ROI 标注、命名和分组。
- 支持同时保存截图像素坐标和 normalized ROI，用于窗口尺寸变化后的坐标重映射。
- 支持 OCR、颜色/图标存在性、简单模板匹配等基础识别方式。
- 支持在运行中周期性或事件触发识别状态。
- 支持将识别结果写入平台字段和本地轨迹。

### 8.4 自动化执行

- 支持点击、双击、输入、快捷键、等待、截图校验、条件分支、循环重试。
- 支持执行前安全检查，例如窗口存在、仪器处于允许状态、参数在安全边界内。
- 支持运行中的暂停、继续、终止与人工接管。
- 支持基于模板 ID + 版本拉取到的工作流生成本地执行上下文。

### 8.5 平台通讯与适配

- 支持通过 FastAPI 与 SpecLabOS 交换任务、配置、状态和日志。
- 支持平台字段映射和格式转换。
- 支持连接保活、失败重试和本地缓存。
- 支持任务下发与模板拉取分离，避免把任务队列接口与模板中心接口混为同一职责。

#### 8.5.1 MVP FastAPI 基线接口

- `GET /health`：用于服务健康检查、联通性确认和运维探测。
- `POST /api/v1/experiment/trigger`：提交 `experiment_plan`，生成本地执行指令并返回 `request_id`。
- `POST /api/v1/experiment/execute`：基于最近一次成功生成的流程发起执行。
- `GET /api/v1/experiment/status`：查询当前执行状态、当前命令、最近触发时间和最新请求标识。

#### 8.5.2 接口行为约束

- `execute` 必须建立在已成功 `trigger` 的前提上，未触发或仍在生成中的请求不得直接执行。
- `status` 是轮询查询接口，不承担暂停、恢复或终止等控制语义。
- 生成失败、状态冲突和下游执行失败必须作为可审计的异常路径记录到运行轨迹和平台日志。
- 平台侧下发模板任务时，不直接跳过标准化和模板解析流程。

### 8.6 日志、监控与审计

- 记录每个步骤的输入、动作、观察结果、执行状态和产物链接。
- 支持运行监控页左侧展示步骤时间线，右侧以标签页区分观测/审计和日志流。
- 支持关键截图回溯、运行时间统计和异常告警。
- 支持实验过程追踪和平台侧审计。
- 支持记录模板发布、模板拉取、版本命中和执行来源。

### 8.7 模板复用与模板中心

- 支持工作流模板、仪器画像模板和平台映射模板。
- 支持模板版本管理、复用和差异说明。
- 支持模板查找、状态过滤、版本时间线、基础更新、增加、删除和回滚操作。
- 当前本地回滚语义为切换当前发布版本，不等同于完整文件历史恢复。
- 支持标准工作流发布时自动上传到 SpecLabOS 备份。
- 支持 SpecLabOS 作为中心模板库保存模板 ID、版本、适用仪器、发布时间和来源。
- 支持平台侧任务按“模板 ID + 版本”模式下发，SmartAccess 拉取模板内容后再执行。
- 支持本地保留模板草稿、校准态和最近执行态，在平台断连时不丢失上下文。

### 8.8 异常告警与恢复

- 支持检测 OCR 失败、窗口异常、按钮缺失、回传失败、状态不收敛等异常。
- 支持重试、回退、等待人工确认、终止运行四类恢复动作。
- 支持把异常上下文完整记录到 `run_trace.jsonl`。
- 支持区分模板拉取失败、模板版本不存在和执行链路失败三类平台相关异常。

### 8.9 工作台与界面框架

- 支持工作台首页展示任务队列、设备状态、最近运行和异常提醒。
- 支持设备接入与校准页展示窗口识别、ROI 标注、锚点配置和字段映射。
- 支持工作流设计页展示模板选择、步骤编排、参数区、预检提示和版本说明。
- 支持模板库页展示模板列表、版本历史、发布状态、适用仪器和回滚/复用入口。
- 支持运行监控页展示当前步骤、观测/审计摘要、日志流和异常恢复动作。
- 采用“左侧导航 + 中央主工作区 + 右侧工具栏”的统一布局原则。
- `xyzen.ai` 的参考仅用于信息架构和交互组织，不约束视觉品牌、主题色或暗色风格。

## 9. 关键流程与状态流转

### 9.1 工作流生命周期

`Draft -> Calibrated -> Standardized -> Published -> Ready -> Running -> Blocked -> Recovered -> Completed -> Archived`

状态说明：

- `Draft`：刚生成或编辑中的草稿。
- `Calibrated`：关键 ROI、锚点和参数映射已完成。
- `Standardized`：已完成校准、字段映射和可复用性确认，满足进入模板中心的条件。
- `Published`：模板已上传至 SpecLabOS 模板中心并具备稳定模板标识与版本。
- `Ready`：前置条件满足，可提交运行。
- `Running`：正在执行自动化动作与状态识别。
- `Blocked`：因异常暂停，等待恢复动作。
- `Recovered`：异常被处理，可继续运行。
- `Completed`：正常执行结束并完成回传。
- `Archived`：本次会话结束，仅保留记录和产物。

### 9.2 典型链路

1. 用户选择仪器并启动校准。
2. SmartAccess 生成 `instrument_profile.yaml` 草稿。
3. 用户通过对话生成 `workflow.yaml`。
4. 工作流完成校准、字段映射和标准化检查后发布到 SpecLabOS 模板中心。
5. SpecLabOS 下发包含 `template_id + template_version` 的任务，SmartAccess 拉取模板内容。
6. 系统执行步骤并持续产出 `run_trace.jsonl`。
7. 平台同步阶段状态、参数、日志和结果。
8. 若异常发生，则依据恢复策略进入恢复链路。

## 10. 非功能需求

### 10.1 兼容性

- MVP 支持 Windows 上位机。
- V1 规划支持 Linux。
- 对仪器厂商不做强耦合要求，但要求可见 GUI 和基础输入能力。

### 10.2 安全性

- 默认只做非侵入式 UI 级操作，不改写仪器原生业务逻辑。
- 需要定义安全限制和人工确认点。
- 高风险动作必须具备可审计和可中止机制。
- 模板发布和模板回滚需要记录操作人和版本说明。

### 10.3 可靠性

- 关键步骤具备重试策略。
- 平台断连时支持本地缓存和补传。
- 关键异常必须产生告警和上下文日志。
- 模板拉取失败时不应覆盖本地最近一次可执行模板副本。

### 10.4 可扩展性

- 新仪器接入应尽量依赖契约和模板，而不是写死脚本。
- 视觉模式、动作原语和平台映射必须可增量扩展。
- 模板中心字段和版本语义必须支持后续扩展审批、审核和模板市场。

### 10.5 可追溯性

- 每次会话都有唯一标识。
- 每个步骤的动作、观测、结果、截图和异常有迹可循。
- 每次模板发布、拉取、执行都能追溯到模板 ID、版本和来源。

### 10.6 性能约束

- 常规截图与状态识别不应显著阻塞执行链路。
- 关键状态识别应满足实验实际节拍要求。
- 平台回传失败时不应直接丢失本地执行记录。
- 模板拉取和状态轮询不应阻塞本地异常恢复链路。

## 11. 部署与权限

### 11.1 部署模式

- 优先采用实验室内网部署。
- 桌面端与仪器上位机同网段或同机运行。
- AI 能力允许云端模型接入，但必须可切换到本地替代。
- FastAPI 服务可与桌面端同进程部署，也可作为本机局部服务暴露给 SpecLabOS。

### 11.2 权限边界

- 科研用户：创建工作流草稿、运行已授权模板、查看自己的日志和结果。
- 管理员：查看监控、模板、异常、配置和模板发布记录。
- 工程师：维护仪器画像、平台映射、模板版本和评测用例。

## 12. 成功指标

### 12.1 MVP 成功指标

- 至少可稳定接入 1 到 3 类典型仪器。
- 单个仪器的首次接入从人工脚本化降到模板化流程。
- 实验关键参数和状态可自动回传平台。
- 标准工作流可发布到 SpecLabOS 并按模板 ID + 版本回拉执行。
- 执行异常具备标准化记录和恢复入口。

### 12.2 V1 成功指标

- 模板复用覆盖多类仪器场景。
- 接入效率、数据完整性和异常闭环能力显著提升。
- 平台可对接更复杂的任务编排和可视化监控。
- 模板治理支持更成熟的审核、回滚和权限控制。

## 13. 风险与待确认项

- SpecLabOS 的真实 API 契约尚未完全落库，需要后续对齐。
- OCR 和视觉识别在复杂 UI、低对比度界面中的稳定性需要专项验证。
- 不同仪器的权限与安全边界差异大，需要分级管控。
- Linux 场景的 UI 自动化技术选型需要在 V1 前确认。
- 模板版本一致性、发布冲突和回滚治理需要在实现阶段进一步细化。
