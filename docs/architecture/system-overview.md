# SmartAccess 系统架构总览

## 1. 文档目标

本文把 `SmartAccess.png` 中的模块关系、数据方向和调用链写成明确的文字架构，供产品、研发和 AI 组件设计共用，并补充 SpecLabOS 模板中心、设备侧 FastAPI 基线接口和工作台信息架构。

## 2. 系统上下文

SmartAccess 位于用户、仪器上位机软件和 SpecLabOS 之间，承担五类责任：

- 接收用户意图并生成可执行工作流。
- 在本地模拟 UI 操作，驱动实验执行。
- 通过视觉识别和运行日志感知真实状态。
- 与 SpecLabOS 同步任务、模板、参数、日志和结果。
- 通过统一工作台承载接入、设计、模板管理和运行监控。

## 3. 分层结构

### 3.1 用户层

- 角色：科研人员、实验室管理人员、平台/自动化工程师。
- 入口：AI Agent 对话、配置界面、模板库、运行监控界面。

### 3.2 SmartAccess 工作台层

- `工作台首页`：展示任务队列、设备状态、最近运行和异常提醒。
- `设备接入与校准页`：承载窗口识别、ROI 标注、锚点配置和字段映射。
- `工作流设计页`：承载模板选择、步骤编排、参数区、预检提示和版本说明。
- `模板库页`：承载模板列表、版本历史、发布状态、适用仪器和回滚/复用入口。
- `运行监控页`：承载当前步骤、截图/识别结果、日志流和异常恢复动作。
- 统一交互框架采用“左侧导航 + 中央主工作区 + 右侧详情/助手上下文”布局。

### 3.3 SmartAccess 核心层

- `AI Agent 交互与配置`：把自然语言意图转为工作流、校准任务和平台适配草稿。
- `工作流生成与管理`：管理模板、步骤、参数、前置条件、标准化状态、发布和版本。
- `自动化操作执行`：把工作流步骤翻译为点击、输入、等待、校验等动作。
- `视觉识别与状态感知`：根据 ROI、OCR、模板匹配和简单规则判断当前状态。
- `平台通讯与适配`：与 SpecLabOS 进行任务下发、模板拉取、模板发布、状态上报和日志同步。
- `日志与监控中心`：承接操作日志、截图、异常告警和性能指标。

### 3.4 平台接口层

- 通过 FastAPI 与 SpecLabOS 双向通讯。
- 支持设备侧实验触发、执行与状态查询基线接口。
- 支持平台侧任务接口与模板中心接口的统一映射。

### 3.5 仪器层

- 包含不同品牌和类型的仪器及其上位机软件。
- SmartAccess 只通过可见界面、键鼠输入和截图读取与其交互。

## 4. 三类主数据流

### 4.1 Action Flow

`用户意图 -> AI Agent -> 工作流/模板 -> 自动化执行器 -> 仪器上位机动作`

特点：

- 以工作流为动作边界。
- 以步骤和前置条件为执行单元。
- 以安全限制和人工确认保护高风险动作。
- 平台下发任务时，先解析模板引用，再生成本地执行上下文。

### 4.2 Data Flow

`仪器界面状态 -> 视觉识别/日志 -> SmartAccess -> SpecLabOS`

特点：

- 关注读数、阶段状态、告警、日志和结果文件。
- 既支持实时上报，也支持本地缓存后补传。
- 关注模板发布、模板拉取和执行来源等平台治理信息。

### 4.3 API Flow

`SpecLabOS -> SmartAccess -> SpecLabOS`

特点：

- 平台下发任务、模板引用和运行参数。
- SmartAccess 根据模板 ID 与版本拉取模板内容，并在标准化后发布模板到平台中心。
- SmartAccess 上报运行状态、实验参数、执行日志、异常和模板来源。
- 平台和本地适配层通过字段映射解耦。

## 5. 运行时调用链

### 5.1 任务启动

1. SpecLabOS 或本地用户发起实验任务。
2. 若任务来自平台，则先获取任务上下文，再按 `template_id + template_version` 拉取模板内容。
3. orchestrator 读取工作流、仪器画像和平台适配配置。
4. executor 准备窗口、会话和动作上下文。

### 5.2 执行与观测

1. executor 执行动作步骤。
2. observer 在关键节点采集截图并解析状态。
3. orchestrator 依据结果决定继续、等待、重试或进入异常。

### 5.3 回传、发布与归档

1. 平台适配层提交状态、参数和日志。
2. 标准化工作流可由工作流管理模块发布至 SpecLabOS 模板中心。
3. 日志中心写入本地轨迹和关键产物路径。
4. 会话结束后归档工作流、日志和截图索引。

## 6. 关键状态流转

### 6.1 工作流状态

`Draft -> Calibrated -> Standardized -> Published -> Ready -> Running -> Blocked -> Recovered -> Completed -> Archived`

说明：

- `Draft`：草稿态。
- `Calibrated`：完成关键 ROI 与锚点校准。
- `Standardized`：完成字段映射、复用性确认和发布前检查。
- `Published`：已同步到 SpecLabOS 模板中心并具备稳定版本。
- `Ready`：可发起执行。
- `Running`：执行中。
- `Blocked`：因异常阻塞。
- `Recovered`：异常已被处理，可继续后续执行或收尾。
- `Completed`：执行与回传已完成。
- `Archived`：会话已归档，仅保留记录与产物索引。

### 6.2 异常状态来源

- UI 找不到目标控件。
- OCR 或视觉结果不可信。
- 平台回传失败。
- 模板拉取失败或平台模板版本不存在。
- 窗口切换、遮挡或权限导致动作未生效。

### 6.3 恢复策略

- 同步重试：轻量错误，例如瞬时识别失败。
- 局部回退：回到上一步或重新定位窗口。
- 人工确认：涉及风险动作或状态不明确时。
- 终止运行：错误超过阈值或安全条件不满足时。

## 7. 平台接口基线

### 7.1 设备侧 FastAPI 接口

- `GET /health`：服务健康检查与联通性确认。
- `POST /api/v1/experiment/trigger`：提交 `experiment_plan`，生成本地执行指令并返回 `request_id`。
- `POST /api/v1/experiment/execute`：基于最近一次成功生成的流程发起执行。
- `GET /api/v1/experiment/status`：查询当前执行状态、当前命令、最近触发时间和请求标识。

### 7.2 架构约束

- `execute` 只能发生在成功 `trigger` 之后。
- `status` 是轮询接口，不承担暂停、恢复或终止控制。
- 平台任务接口与模板拉取接口职责分离，避免 `fetch_task` 与 `fetch_template` 混用。

## 8. 部署拓扑

### 8.1 MVP

- SmartAccess 桌面端与上位机同机或同网段部署。
- FastAPI 适配层可与桌面端同进程或局部服务化。
- SpecLabOS 位于实验室内网管理侧。
- 模板中心由 SpecLabOS 承载，设备侧保留最近可用模板副本。

### 8.2 V1

- 支持更清晰的本地执行器与集中监控分离。
- 支持多仪器画像、多会话和更系统化的任务队列。
- 支持更完善的模板治理、发布审批和版本回滚。

## 9. 架构边界

### 9.1 SmartAccess 负责

- UI 级执行、视觉感知、工作流编排、模板发布、模板回拉、日志与平台同步。

### 9.2 SmartAccess 不负责

- 替代仪器驱动层。
- 覆盖厂商安全联锁逻辑。
- 跳过权限与审批直接执行危险动作。
