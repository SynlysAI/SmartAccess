# SmartAccess v2 PyQt 客户端界面重构设计

## 背景

SmartAccess v2 通过 `run_desktop_v2.py` 启动 `src/smartaccess_v2` 下的 PyQt6 桌面客户端。当前设备接入与校准、工作流设计等核心功能逻辑已经跑通，但界面仍接近 Qt 默认样式，存在视觉陈旧、区域边界不清、表格控件拥挤、导航状态不够明确等问题。

本次设计聚焦表现层重构，不改变运行时、ViewModel、数据契约和业务行为。

## 目标

- 建立现代 Web 风格的浅色桌面工作台视觉基线。
- 用卡片式结构区分表单区、图片区、列表区和表格区。
- 优化左侧导航、按钮、表单控件和表格可读性。
- 优先使用现有 PyQt6 标准控件和全局 QSS 快速交付第一版效果。
- 为后续按需引入 `qfluentwidgets` 保留空间，但第一阶段不新增强依赖。

## 非目标

- 不重写业务流程、运行时编排、ViewModel 或持久化逻辑。
- 不在第一阶段替换为完整 qfluentwidgets 架构。
- 不引入复杂动画、深色主题或多主题切换。
- 不新增大范围自动化测试；本阶段以界面启动和人工视觉验收为主。

## 视觉方向

采用“平衡型工作台”密度，而不是过度留白的展示型界面：

- 主窗口背景：`#F5F7FA`。
- 内容卡片：白色背景、`8px` 圆角、细边框和极浅阴影。
- 主要间距：页面外边距约 `20px`，卡片和主要区域之间约 `16px`。
- 字体：继续使用 `"Segoe UI", "Microsoft YaHei", sans-serif`。
- 主色：蓝色系，Primary 按钮和导航选中态统一使用同一主色。
- 文本层级：页面标题加粗，辅助说明使用低饱和灰蓝色。

## 技术路线

第一阶段采用混合方案中的低风险部分：

1. 扩展 `src/smartaccess_v2/desktop/shell/theme.py` 的全局 QSS。
2. 在页面和容器上补充稳定的 `objectName`，用于卡片、导航、按钮和表格样式定位。
3. 调整布局边距、间距、表格属性和控件最小高度。
4. 保持所有信号连接、ViewModel 调用和数据读写逻辑不变。

第二阶段作为后续可选增强：

- 评估 `qfluentwidgets` 用于图标、Fluent 导航、提示条、对话框等高价值组件。
- 只有在第一阶段样式稳定后，再决定是否新增依赖并替换局部控件。

## 组件设计

### 主窗口

- `QMainWindow` 和中心区域使用浅灰背景。
- 顶部栏保持轻量，不做营销式大标题。
- 右侧上下文栏保持独立白色区域，边界更轻，避免抢占主工作区注意力。

### 左侧导航

- 导航宽度保持接近当前尺寸，增加条目高度和垂直间距。
- 每个导航项预留图标位置，第一阶段可使用文本前置留白或后续图标对象承接。
- 选中项使用浅蓝背景和左侧蓝色竖线。
- 去掉默认列表粗边框和焦点虚线。

### 卡片容器

表单区、窗口列表、截图画布、锚点表格、工作流列表、工作流编辑区、结果区都应具备清晰区域边界：

- 使用 `QFrame#Card` 或具体对象名样式实现卡片。
- 卡片内部保留合适 padding。
- 页面仍可使用 `QSplitter` 保持现有可调整布局能力。

### 表格

表格是第一阶段重点优化对象：

- 行高至少 `40px`，步骤表建议 `46px`。
- 隐藏垂直网格线，只保留极浅水平分隔线 `#EBEBEF`。
- 去除表格外层粗边框，使用轻边框或卡片边界承载区域边界。
- 表头使用浅灰背景、加粗文字和底部分隔线。
- 单元格内的 `QComboBox`、`QLineEdit`、`QDoubleSpinBox` 保持足够高度和 padding。
- 表格行操作按钮缩小视觉重量，删除按钮保持红色危险态。

### 按钮与表单

- Primary：保存、截图、添加锚点等主要动作，蓝色实心。
- Secondary：新建、检查、扫描、AI 生成等辅助动作，白底灰边。
- Danger：删除和危险操作，浅红背景或红色边框。
- 输入框、下拉框、文本框统一圆角、边框、hover/focus 状态和 padding。

如果发现某个页面缺少可复用卡片容器，可以新增一个很薄的桌面 UI helper，但优先避免过度抽象。

## 验收标准

- 使用 `run_desktop_v2.py` 启动后，主窗口不再呈现默认 Qt 视觉。
- 设备接入与校准页面的表单、窗口列表、截图画布和锚点表格有明确卡片分区。
- 工作流设计页面的工作流列表、元数据表单、AI 输入、步骤表和结果区布局更清晰。
- 表格行高和单元格控件不贴边，水平分隔线轻，垂直网格线不可见。
- 左侧导航有图标预留位和现代选中态。
- 主次按钮样式可区分，删除类按钮有危险态。
- 第一阶段不破坏现有功能交互。

## 验证方式

- 运行现有桌面 smoke 测试，确认基本窗口构建未破坏。
- 使用 `run_desktop_v2.py` 启动应用进行人工视觉检查。
- 必要时使用浏览器或截图工具辅助对比，但 PyQt 可视验收以桌面窗口为准。

## 风险与处理

- QSS 对不同控件子元素支持不完全一致：优先使用稳定选择器和对象名，避免过深选择器。
- 表格内嵌控件较多，行高和控件高度需同步设置：在表格组件初始化中设置默认行高和控件最小高度。
- qfluentwidgets 后续引入可能影响依赖和打包：第一阶段只预留风格和对象边界，不直接绑定该依赖。
